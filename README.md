# mkcloud IXP：上云互联优化专线选购指南，覆盖深港/沪日/沪港/沪美四条线路、实测延迟与全套餐价格拆解

很多用户在搜 `mkcloud IXP` 时，真正想搞清楚的事情其实比"找一家便宜的跨境专线"要多：MKCloud 这家 2023 年成立的专线服务商究竟是怎么把 IX 和上云互联两条概念揉在一起的；现有四条 IXP 线路（深港、沪日、沪港、沪美）各自的延迟、入口要求和价格档次怎么排；哪些套餐是流量计费型、哪些是独享带宽型、哪些是给企业团队定制的；优惠码现在还能不能用；前置云厂到底要不要自己再买一台机器。如果你正在评估"已经买了阿里云/腾讯云，要不要在 MKCloud 接一条 IXP"，这篇文章尽量把这些事实摆清楚。

## MKCloud 与 IXP 是什么关系

MKCloud（mkcloud.net）是 2023 年 11 月成立的国内专线服务商，主体公司为 MKADMD，运营至今接近三年。它把业务划成了三类专线：IEPL（广港方向）、IPLC（沪港/沪日/沪美/港法方向）以及 IX（互联网交换中心，对外宣传为 "IXP 上云互联优化"）。三类产品的共同点是：每一台 VPS 都分配 1 个独立入口 IP 和 1 个独立出口 IP（双独享 IP 组合），用户连接入口，在 VPS 里调用业务，流量从出口自动发出；出口本身不接受外部连入，因此不能作为公开站点、支付回调或游戏服务端。

IX 这个概念在这里值得多解释几句。IXP（Internet Exchange Point）是互联网交换中心，可以让不同网络在同一物理位置直接交换流量。MKCloud 的做法不是让你去申请 IXP 成员资格，而是把前面那一段（从国内到你出口目标）做成了对外零售的 VPS：入口挂在深圳/上海的"云厂优化网络通道"上，终点连到香港/日本/美国的 BGP 出口。这样你不是在对接 IX 本身，而是搭 MKCloud 这条捷径绕过公网常见的跨网路由和 QoS 问题——深港端内参考 1\~2ms、沪港 21ms、沪日 25\~28ms、沪美 124\~134ms 等数据都来自 MKCloud 产品资料，不是到目标网站的完整 RTT。

这条思路对应的官方表述叫"上云互联优化专线（IXP）"。云厂接入、入口隐藏在云厂内网，公网扫描不到入口 IP，因此抗 DDoS 和抗通报都更稳一些。但代价是：必须自己准备一台支持范围内的云厂机器（阿里云/腾讯云/百度云/火山云/华为云/UCloud，具体看入口）作为前置，前置云机的费用是 IXP 套餐之外的成本。

## IX、IEPL、IPLC 三类产品的取舍

MKCloud 官网首页把产品按线路类型分得很清楚，三者侧重点不同：

- **IEPL（广港专线方向）**：入口绑定广东一个省份（广州 BGP/广东移动/广东电信/广东联通/三线动态中选一），绑定的省份可自行切换，端内 1\~2ms。适合没有云前置、想用本地宽带或办公室网络直接连入的用户。官网起步价标的是广港 IEPL ¥358/月起。
- **IPLC（沪港/沪日/沪美/港法方向）**：与 IEPL 类似，绑定省份，沪港 21ms、沪日 25\~28ms、沪美 124\~134ms。沪美 IPLC 1TB 流量档在购物车页面标价为 ¥428/月。
- **IX（深港/沪日/沪港/沪美 IX 方向）**：入口是云厂优化网络通道，不限连入省份但必须用支持范围内的云机连入；同方向价格普遍比 IEPL/IPLC 略低。

按 MKCloud 的官方选型指南，IEPL/IPLC 与 IX 的核心差别其实只在接入方式：直连款绑定省份、IX 走云厂网络；前者"开箱即用"，后者需要你已经有合适的云资源。如果你的业务已经跑在阿里云/腾讯云/华为云上，IX 同等价格能拿到更高的带宽或流量，并多一份入口隐藏带来的安全冗余；如果业务是办公网或家庭宽带，IEPL/IPLC 的绑定省份入口更顺滑。

## 接入条件：你需要先有云前置

IXP 不是"装上就能用"，MKCloud 官方知识库明确列出：IX 入口连接需要在支持范围的云厂机器上发起，家庭宽带和手机流量不能在公网直接连入入口 IP。

- **深圳入口**：阿里云、腾讯云、百度云国内全网，以及火山云、华为云华南。
- **上海入口**：阿里云、腾讯云、百度云国内全网，以及火山云、华为云、UCloud 华东。

如果你已经在跑上述云厂的业务机，把 IP 段解析好之后，从这台云机 ping 入口 IP 是连得通的，这是判断能否接入的最快办法。具体的网络配置步骤在知识库《IX 专线怎么选》一文中给出，本质步骤是：准备符合要求的云机 → 从其连接 IX 入口 → 在 IX VPS 内运行程序 → 确认出口走的是 MKCloud 提供的香港/日本/美国 IP。

需要注意的是，MKCloud 在产品定位中着重说明，IXP 不会自动把你前置云机或公司所有应用的路由都改掉，它只为这台 VPS 提供出口指向。同一个办公网络下的其它主机，仍然走原来的默认路由。

## 实测数据：端内延迟、出口带宽、稳定性

VPSDeck 与 catcat.blog 两位独立测评者都做过 MKCloud 沪港 IXP / 沪日 IXP 的连测，数据来自他们的公开报告（非 MKCloud 自报），下面整理核心结论：

- **沪港 IX 入口**（腾讯云北京 CVM 出发）：平均 30ms，15 次长 ping 0% 丢包；阿里云上海轻量云出发：平均 8ms，公网 itdog 一片红（验证 IX 入口无法公网直连）。
- **沪港 IX 出口方向平均延迟**：香港 HKT 21.5ms、台湾 HiNet 76.1ms、台湾 SeedNet 35.1ms、新加坡 Singtel 105.4ms、新加坡 CDN77 63.0ms、越南 FPT 59.6ms。
- **沪港 IX 出口带宽**：到香港 Zouter HKG 实测跑满 300Mbps（峰值 500Mbps 未跑满，测评者认为是测试环境限制）；到新加坡 Oracle Cloud 仅 100Mbps，受国际公网损耗影响。
- **沪日 IXP 系统基准**（Amazon EPYC-Rome 平台）：磁盘 IO 4k/64k 读写均在 100\~190MB/s 区间；Geekbench 5 单核 921\~935、多核 1757\~1859。
- **系统兼容**：Debian 12/13、KVM 虚拟化、支持 AES-NI，IPv4 在线、IPv6 默认关闭。
- **稳定性口径**：MKCloud 自述年度突发故障约 3 次，提前通知的维护不算；默认无 SLA 保证；可付费定制 SLA。

这套数据的实际意义是：沪港 IX 端内 21ms 这个数字是真的，但用户到目标服务的完整 RTT 取决于前置 + 入口 + 出口 + 目标链路四段拼起来的结果，按上方 VPSDeck 的长 ping，香港 HKT 出口约 21.5ms 已基本与宣传吻合。

## 退款、SLA 与售后服务边界

MKCloud 的服务条款（TOS）和退款知识库反复强调几条硬约束，建议下单前确认：

- **退款窗口**：仅开通后 24 小时内、且产品存在"质量问题"才能申请退款。开通后不支持更换到其他地域的产品。
- **SLA**：默认无 SLA 保证。SLA、路由定制、高防参数和售后响应时长等细节未公开，需要 SLA 的企业团队可联系工单付费定制。
- **实名认证**：必须完成实名认证；服务协议与隐私政策规定了实名信息使用范围。MKCloud 自述对"正规用途"的定义是"不进行回国等违法行为即为合规用途"。
- **支付与平台**：支持多用支付与多平台联动；TOS 同时覆盖 DDoS 被攻击、明显欺诈、有意服务滥用情况下不退款。
- **升降级**：升降级均需工单操作。降级到更低价格套餐时差价不退。

## 典型适用场景与不适合的场景

适合用 mkcloud IXP 的场景：

- 已在阿里云/腾讯云/华为云的跨境电商业务，需要一条带"入口隐藏 + 多出口对等"的捷径保护账号安全；
- 多账号运营（亚马逊、TikTok Shop、eBay、Shopee 等）对独立 IP 和抗通报有要求的运营团队；
- 通过 API/SDK 调用海外服务（地图、支付、物流、SaaS API）的应用方；
- 已有云前置预算，希望把"前置 + 出口"的总成本算清楚后再选档位。

不适合直接上 IXP 的场景：

- 业务跑在家庭宽带或办公室网络、没有云前置——IXP 拉不起来，这时更合适的是 IEPL/IPLC 的"绑定省份"方案（如广港 IEPL、沪日 IPLC）；
- 需要把 IK 提供给同事或客户主动连入、或者开公开回调——IXP 出口不能接收入站；
- 不希望自购云厂前置、又想要内网隐藏效果——这种组合目前在 MKCloud 公开资料里找不到。

## 常见问题

**Q1：IXP 一定要有云厂前置吗？**
是的。MKCloud 在《IX 专线怎么选》中明确：IX 不是任意公网环境直连，必须从支持范围内的云厂机器连入。家庭宽带和手机流量无法直接连 IX 入口。

**Q2：IX、IEPL、IPLC 的核心差别是什么？**
入口接入方式不同。IEPL/IPLC 是绑定省份、对应入口省份的 IP 都能连；IX 是不绑省份，但必须从支持的云厂网络连入。后者入口隐藏在云厂内，所以在抗 DDoS 和抗通报方面多一层冗余，代价是需要自配云前置。

**Q3：每台 IXP VPS 都给独立 IP 吗？**
是的。MKCloud 全线产品都是双独享 IP：1 个独立入口 IP + 1 个独立出口 IP。共享/独享的差别主要在带宽模式，不在 IP 共享。

**Q4：超量真的会暂停吗？**
